# 事件分类 → 标准动作模板

这份表是系统的「运营 Know-how」载体：把代码里的判定条件翻译成人话，再补上**你实际会执行的动作**。

它的左半边已经在 `src/analysis/diff.py` 里了（7 类判定的 `if` 分支 + `P0_DROP_RATIO` 等阈值常量），右半边需要你按自己店铺的实际情况补充。

填写原则只有三条：

1. **写终点，不写过程** —— 「重点关注竞品投放」不合格，「把『XX 词』出价从 0.8 提到 1.2」才合格。
2. **只写你真做过的** —— 编出来的策略执行不了，还会污染提示词。写不出说明那类你根本用不上，删掉即可。
3. **≤ 8 行** —— 每多一行，7B 级别的小模型就多一处漏规则或串台的机会。

## 落地方式三选一

| 写法 | 适用 | 代价 |
|---|---|---|
| ① 写成提示词文本（贴进系统提示词） | 起步阶段，≤ 8 行 | 改策略要重跑验证 |
| ② 用「条件分支」节点做硬判断 | 类别 > 8 或要求 100% 不漏 | 分支图会变复杂 |
| ③ 混合：分支定 `category`，LLM 只做归因 + 复核 | **推荐** | — |

选 ③ 的理由与项目主设计原则一致：**分级这类确定性判断交给规则，LLM 只干它会变的那部分**（为什么变、合不合理、要不要推送）。

## 模板表

下表是当前 `prompts/analysis_v3.txt` 中已落地的版本，可直接作为起点修改：

| 事件类别 | 判定条件 | 归因要点 | 标准动作模板（终点态） |
|---|---|---|---|
| 自有降价异常 | self + price + 降幅 ≥10% | 先怀疑误操作 vs 主动促销 | 查商家后台改价记录；误操作 → 立刻改回 old_value；主动促销 → 核对活动配置与券叠加 |
| 自有普通调价 | self + price + 其他情况 | 常规调价 | 确认与活动节奏一致即可 |
| 自有下架 | self + listing_status → off_shelf | 故障，非情报 | 查是平台违规下架还是缺货，恢复上架或补库存 |
| 自有断货 | self + stock → 0 | 事故 | 立即补货，或把该 SKU 设为缺货预售 |
| 竞品降价 | competitor + price + 降幅 ≥5% | 情报，需评估是否跟 | 对照跟价阈值：跟 → 写出新价并做利润校验；不跟 → 记录价差 |
| 竞品下架 | competitor + listing_status → off_shelf | 机会 | 接手流量：抢该商品核心关键词投放，检查自家承接页是否就绪 |
| 竞品断货 | competitor + stock → 0 | 机会 | 抢该词流量，确认自家该词库存接得住 |
| 主图换版 | main_image 变化 | 视觉策略调整 | 评估与自家主图的视觉差距，向美工提素材需求 |
| 标题改卖点词 | title 变化 | 卖点词增删 | 核对新增核心词是否值得跟，必要时补同类卖点词 |
| 促销机制变化 | promotion 变化 | 活动机制变化 | 核对活动配置，评估自己是否要出对应券 |
| 评分下滑 | rating 下降 ≥0.2 | 风险信号 | 排查近 30 天差评来源 |
| 归属未知 | role = unknown | 归属未确认 | 人工确认归属后再定（**不要猜方向**） |

## 自检清单

改完这张表后，用这几条过一遍：

- [ ] 有没有「过程型」描述（重点关注 / 加强关注 / 优化一下）→ 打回重写
- [ ] 有没有硬塞进你从没执行过的动作（说明在编策略而非整理经验）→ 删掉
- [ ] 行数是否 ≤ 8；超了要砍
- [ ] 每条动作是否都有**明确终点态**（改成 X / 立刻改回 Y / 保持不变 / 不要跟价）

## 改完之后

对应改动落在两处：

1. **`prompts/analysis_v3.txt`** —— 同步更新「各类标准动作模板」段落
2. **`dify/taobao-monitor-v3.yml`** —— 如果用的是导入的 DSL，需要同步更新 LLM 节点的系统提示词

改完**不要直接在 Dify 界面里试**，先跑本地回归：

```bash
python scripts/verify_dify_dsl.py
```

同一份提示词改一个字都可能让 7B 模型换一种输出写法，没有回归就是在赌。全部通过再导入。
